# Ответы клиентов и отказы — исправление 14.09.2026

## Первопричина

`process_imap_tick` передавал каждое письмо только в `apply_dsn_bounce`.
Обрабатывались технические постоянные возвраты доставки (DSN). Обычное письмо
получало `outcome=unrecognized`, сохранялось в таблице обработанных UID, а курсор
продвигался вперёд. Распознавания ответа клиента и перехода в `rejected` не было.
Повторный проход такого письма уже не выполнялся. Проверка только INBOX также
оставляла вне обработки письма, перемещённые в другие папки.

Дополнительные проблемы: ручная отправка не проверяла статус `rejected`, а успешное
завершение SMTP безусловно записывало `sent`, в том числе после более свежего отказа.

## Реализация

- `services/inbound_replies.py`: разбор MIME, кодировок, plain text и HTML; исключение
  цитат, подписи FuelLead, автоответов и рассылок с соответствующими заголовками.
- Поддержаны явные отказы в тексте и короткой теме письма. Реальный случай:
  «Контакт-Сервис» ответил темой «Не писать», оставив в теле только цитату предложения.
- Привязка по `In-Reply-To`/`References` к доставке кампании или истории одиночной
  отправки; резервная привязка по точному адресу контакта. Неизвестный отправитель
  без связи с компанией не изменяет её статус.
- Отказ переводит компанию в `rejected` и добавляет её адреса в глобальные исключения
  `client_refusal`. В `activity_history` сохраняются источник, идентификатор письма,
  папка, UID, фрагмент ответа и сработавшая фраза. Обычный ответ переводит `new/sent`
  в `answered`, сохраняя более поздние статусы.
- Изменение компании, исключения и обработанный UID фиксируются одной транзакцией.
  Идентификатор ответа предотвращает дубли при переносе между папками и повторном
  сканировании после изменения UIDVALIDITY.
- Новая аддитивная таблица `imap_reply_folders` создаётся штатным `create_database`.
  Она хранит отдельные курсоры/UIDVALIDITY для спама, корзины и пользовательских
  папок. Исходящие, черновики и недоступные для выбора папки исключены.
- При ручной установке «Отказ» также создаются исключения. Ручная отправка отклоняется,
  плановая очередь повторно проверяет актуальный статус перед отправкой, а завершение
  уже выполнявшегося SMTP больше не затирает отказ или ответ клиента.

## Повторная обработка существующей переписки

Команда по умолчанию выполняет проверку без сохранения изменений:

```sh
docker compose exec -T backend python -m app.commands.reprocess_replies
```

Применение найденных ответов и исключений для уже отмеченных отказов:

```sh
docker compose exec -T backend python -m app.commands.reprocess_replies --apply
```

## Реальный сквозной тест

Тест выполнен между двумя уже подключёнными ящиками владельца. Массовая кампания
№120 оставалась `paused`; `OUTREACH_AUTOMATIC_SEND_ENABLED=false` сохранён.

1. Создана отдельная неактивная тестовая компания **№9900**, чтобы она не участвовала
   в поисковой/массовой выборке.
2. В 11:27:49 MSK штатный сервис FuelLead `send_test_message` завершил отправку из
   ящика №2 в ящик №3: SMTP `250`, копия в «Отправленных» сохранена. История отправки
   привязана к тестовой карточке. Использован сервис тестовой отправки; массовая
   кампания для обхода ограничения интерфейса не останавливалась и не возобновлялась.
3. Фактическое получение исходного письма подтверждено по Message-ID в INBOX второго
   ящика, UID **235**.
4. В 11:28:07 MSK из второго ящика через реальный SMTP отправлен ответ
   **«не пишите мне больше»**, с `In-Reply-To` и `References` исходного письма.
   До обработки карточка оставалась `sent`.
5. Для немедленного штатного прохода перезапущен IMAP-worker. Он получил ответ в
   INBOX ящика №2, UID **150**, автоматически записал `outcome=rejected`, изменил
   карточку на **«Отказ»** и создал глобальное исключение. Ручного изменения статуса
   после ответа не выполнялось.
6. Событие истории **№64604** содержит точную фразу ответа. Авторизованный запрос
   API карточки вернул `status=rejected`. Попытка повторной отправки через настоящий
   endpoint `/api/companies/9900/send-email` вернула **HTTP 409**:
   «Компания отказалась от дальнейших писем»; новое письмо не отправлялось.

Тестовая карточка сохранена неактивной со статусом «Отказ» и одним событием ответа.
Проверка интерфейса браузера остановилась на форме входа; сквозное доказательство
получено из реальных SMTP/IMAP, работающего worker, базы и авторизованного HTTP API.
