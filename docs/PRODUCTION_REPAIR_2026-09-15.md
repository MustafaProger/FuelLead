# Проверка и исправления сервера — 15 сентября 2026

Сервер: `130.49.151.239`, проект `/opt/fuellead`, исходный Git HEAD `bcd91c0`.
Проверка и обновление выполнены через SSH. Пароли и почтовые сообщения в отчёт не включены.

## Результат

1. **Личные переписки исправлены и обновлены на сервере.** На HTTP браузер не
   предоставляет `crypto.randomUUID`; вызов при создании черновика обрывал рендер
   выбранной переписки. Добавлен криптографический UUID v4 через `getRandomValues`,
   сохранив прежние идентификаторы черновиков и защиту от повторной отправки.
2. **Ускорено открытие «Отправить письма».** При существующей рассылке интерфейс
   получает её состояние без повторного создания снимка всей базы. Подготовка новой
   выборки не загружает полную историю компаний, контакты и дополнительные ОКВЭД;
   текст писем формируется только для получателей текущего снимка.
3. **Восстановлена фоновая проверка входящих.** Контейнер `imap-worker` отсутствовал.
   Он создан с политикой `restart: unless-stopped`; все четыре ящика успешно прошли
   IMAP-проверку после запуска. Интервал проверки — 300 секунд.
4. **Текущее SMTP-подключение на 465 остаётся недоступным.** TCP-соединение не
   устанавливается ещё до TLS/авторизации. Дополнительная проверка обнаружила
   доступный Mail.ru 2525 с STARTTLS; для его использования потребуется поддержка
   STARTTLS в приложении. Авторизация и отправка через 2525 ещё не проверены.

На сервере повторены проверки обоих IPv4 Mail.ru; Gmail и Яндекс 465/587 также
недоступны. На 2525 проверка прошла с хоста и из backend-контейнера: `EHLO 250`,
поддержка STARTTLS, `STARTTLS 220`, TLS с проверкой сертификата и имени `smtp.mail.ru`
за 0,035–0,045 с. Этот альтернативный порт указан в
[официальной справке Mail](https://help.mail.ru/developers/errors/).

На Mac активен v2RayTun, обычный маршрут идёт через `utun5`. Для сравнения только
диагностические сокеты были привязаны к существующему Wi-Fi-интерфейсу `en0`
через `IP_BOUND_IF`; VPN и таблица маршрутов не изменялись. Прямой Wi-Fi прошёл
SMTP465/TLS/приветствие за 0,232 с, тогда как через VPN TLS истёк по таймауту 8 с.

У сервера обычный маршрут `ens3 → 192.168.0.1`, стандартные policy rules,
VPN-интерфейсов и специальных VPN-маршрутов нет. Proxy-переменные отсутствуют в
проверенных окружениях SSH/backend. VPN Mac влияет на локальные подключения,
но не участвует в соединении удалённого backend с Mail.ru.

Недоступность 465 зависит от сетевого пути, а не от отсутствия домена или
сертификата сайта. Точная сторона, фильтрующая серверный трафик, не установлена.
В текущем `MailruSMTPClient` используется `SMTP_SSL`: простой смены числа 465 на
2525 недостаточно, требуется `SMTP → EHLO → STARTTLS → EHLO → AUTH` с обязательной
проверкой сертификата. В рамках этой дополнительной проверки SMTP-настройки,
кампании и код приложения не изменялись; AUTH и отправки не выполнялись.

## SMTP: доказательства и следующий шаг

- `check_mailboxes --network --network-timeout 8`: SMTP Mail.ru — DNS доступен,
  TCP недоступен; IMAP Mail.ru — DNS/TCP/TLS/приветствие доступны.
- С хоста: Mail.ru 25/465/587, Gmail 465/587, Яндекс 465/587 завершаются таймаутом.
  IMAP993 всех трёх провайдеров и HTTPS443 доступны.
- Из backend-контейнера недоступны оба IPv4 SMTP Mail.ru: `94.100.180.160`
  и `217.69.139.160`, порт 465; IMAP/HTTPS доступны.
- UFW разрешает исходящие подключения, `OUTPUT ACCEPT`; `DOCKER-USER` и
  `ufw-user-output` пусты; исходящий трафик Docker разрешён.
- Захват сетевых заголовков на `ens3` показал исходящие SMTP SYN без ответа,
  при этом соседняя проверка IMAP успешно установила соединение.
- Сохранённые пароли всех четырёх ящиков расшифровываются. SMTP AUTH не проверен:
  до него соединение не доходит. Рабочая настройка Mail — `smtp.mail.ru:465`, SSL/TLS,
  согласно [официальной инструкции](https://help.mail.ru/mail/login/mailer/).

Вероятна фильтрация исходящего SMTP на стороне хостинга или выше по сети.
Точное место ограничения должен подтвердить провайдер. Текст обращения:

> На сервере 130.49.151.239 не устанавливаются исходящие TCP-соединения к
> smtp.mail.ru:465 (94.100.180.160 и 217.69.139.160). Аналогично недоступны
> SMTP465/587 Gmail и Яндекс. IMAP993 и HTTPS443 работают. OUTPUT разрешён;
> tcpdump фиксирует исходящие SYN без ответов. Просим проверить и снять
> ограничение исходящих SMTP-соединений, прежде всего TCP465.

После снятия ограничения повторить сетевую проверку и `check_mailboxes --verify`
(без отправки письма), затем проверить разрешённую пользователем отправку.
Альтернативный путь по результату дополнительной проверки — добавить поддержку
2525/STARTTLS, затем отдельно проверить авторизацию и разрешённую отправку.
