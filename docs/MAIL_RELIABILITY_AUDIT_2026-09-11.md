# Повторный сбой почты FuelLead — 11 сентября 2026

## Итог и границы проверки

Изучен предыдущий почтовый коммит `a90c172`, текущие SMTP/IMAP-сервисы, планировщик,
формы, шифрование, контейнеры и фактические ошибки. Исправления установлены в локальные
Docker backend, imap-worker и frontend. Это не проверка отдельного удалённого сервера.

Программные причины устранены и проверены 352 тестами внутри собранного Docker-образа.
Рабочая отправка пока заблокирована внешними условиями: текущий маршрут v2RayTun
не пропускает SMTP, а Mail.ru отклоняет IMAP-вход `artel.work@mail.ru`.
Пользователь явно попросил VPN не менять. Настройки VPN, маршруты и пароли не менялись.
Реальные письма не отправлялись; доставка новых писем не проверена.

### Уточнение после сообщения пользователя

Пользователь сообщил, что при обычном входе `artel.work@mail.ru` Mail.ru показал
блокировку из-за подозрительной активности. Это указывает на защитную блокировку
самого аккаунта; прежний отказ IMAP не доказывал неверность пароля приложения.
Ящик №2 отдельно приостановлен в FuelLead (`is_active=false`), запланированные
автопроверки сняты. Остальные ящики не менялись, кампания №63 остаётся на паузе.
Для этого аккаунта сначала нужно восстановить доступ на сайте Mail.ru, затем
проверять пароль приложения. Причина срабатывания защиты Mail.ru не установлена;
нельзя утверждать, что блокировку вызвал именно VPN.

## Остальные исправления

- Коды отсутствующего получателя отделены от ошибки адреса отправителя, переполненной
  квоты и слишком большого письма; квота не считается доказательством несуществующего адреса.
- Сохранены безопасные подробности AUTH и числовой SMTP-код; пароли и закодированные
  AUTH-пакеты скрываются. Ошибка EHLO проверяется до входа.
- Добавлены обработка кириллических доменов через IDNA, проверка адресов и заголовков
  до подключения, отбрасывание невидимых символов в пароле приложения.
- Проверки SMTP и IMAP независимо сохраняют результаты. Фоновое чтение IMAP не отменяет
  медленную SMTP-проверку. Старый пароль или запоздалый ответ не перезаписывают новую проверку.
- Сбой проверки одного аккаунта не мешает остальным. IMAP-проблема папки/протокола/TLS
  повторно проверяется с сохранением проверки сертификата; постоянный отказ AUTH не перебирается.
- Запись копии в «Отправленных» не требует доступного INBOX и не отменяет SMTP 250.
- Ошибка FETCH не продвигает курсор через непрочитанное уведомление. Добавлен UIDVALIDITY:
  смена нумерации сообщений сбрасывает только служебный учёт UID данного ящика,
  сохраняя историю доставок и исключения.
- Если все отправители требуют исправления, кампания показывает понятную причину паузы.
- При неудаче формы замены пароля/теста остаются открытыми с введёнными значениями.
  Статус «SMTP подключён» не утверждает доставку во «Входящие». Есть отдельные подсказки
  для сети/VPN и отказа авторизации.

## Что необходимо для реального возобновления

1. Обеспечить доступ к SMTP через разрешённую пользователем сеть. Текущий VPN-маршрут
   остаётся неизменным и продолжает блокировать SMTP. Код FuelLead этого не исправит.
2. Для `artel.work@mail.ru` проверить доступ IMAP/SMTP во внешних сервисах Mail.ru и
   сохранить действующий пароль приложения в форме FuelLead. Если нужен IMAP, Mail.ru
   указывает режим «Полный доступ к Почте»; режим «Только отправка писем» не даёт IMAP.
   Пароль вводится пользователем непосредственно в приложение, не в чат.
3. После успешной проверки SMTP возобновить кампанию вручную. Проверку фактической
   доставки выполнять отдельным письмом только на явно подтверждённый адрес.

Диагностика без входа и отправки:

```bash
docker compose exec -T backend python -m app.commands.check_mailboxes --network
```

Проверка входа и обновление статусов, также без отправки:

```bash
docker compose exec -T backend python -m app.commands.check_mailboxes --verify
```

Отсутствие будущих ограничений провайдера гарантировать нельзя. Mail.ru документирует
почасовые ограничения и не рекомендует рассылки с личных ящиков. Для регулярных рассылок
сервис рекомендует собственный домен и Postmaster; переход требует отдельного выбора
пользователя, в этой работе он не выполнялся.
