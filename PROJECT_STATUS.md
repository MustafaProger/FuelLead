# FuelLead — состояние проекта

## Назначение и документация

Внутреннее приложение для поиска компаний, рассылки коммерческих предложений и
работы с перепиской. Стек: FastAPI / SQLAlchemy / PostgreSQL и React / TypeScript.
Запуск, переменные окружения и API описаны в [README](README.md), работа в интерфейсе —
в [инструкции пользователя](docs/USER_GUIDE.md). Инструкция импортируется frontend;
она нужна для сборки и раздела помощи.

## Эксплуатация

- Production находится в `/opt/fuellead`. Caddy направляет запросы на
  `127.0.0.1:18080`, который публикует frontend через `compose.production.yml`.
- При обновлении конкретного сервиса используйте из каталога проекта:
  `docker compose -f docker-compose.yml -f compose.production.yml up -d --no-deps <service>`.
  Запуск без production override может нарушить порты и привести к HTTP 502.
- Рабочие данные хранятся в PostgreSQL volume. Перед изменением данных или схемы
  нужна свежая резервная копия; копии хранятся вне каталога исходников.
- Пароли, ключ шифрования и остальные секреты находятся в `.env` и рабочей БД.
  Их нельзя переносить в Git, отчёты или логи.

- API-ФНС исключён из новых запусков поиска. Используются Checko, Okvedo и DaData.
- Старое значение `DISCOVERY_PROVIDER=api_fns` выбирает оставшиеся настроенные
  источники. Если их нет, поиск сообщает об отсутствии API, без добавления демо-компаний.
- Сохранённые компании, курсоры и история старых запусков остаются без изменений.
- Локально: 832 теста пройдены, 13 PostgreSQL-проверок пропущены; сборка frontend

- На production обновлены только backend и imap-worker. Введены защитные бюджеты
  автоматической кампании: 5 попыток за скользящий час и 20 за 24 часа на ящик.
  Это настройки FuelLead, не гарантированные лимиты почтового провайдера.
- Rate limit, блокировка отправителя и suspicious activity останавливают кампанию

- Все 845 тестов прошли в отдельном контейнере на сервере, включая изолированный
  PostgreSQL. Временные тестовые ресурсы удалены после проверки.
- Проверены код работающего контейнера, реальные PostgreSQL-запросы бюджета,
  авторизованные API (200), публичная страница (200). Все шесть ящиков прошли

  пароля приложения сейчас не воспроизводятся; исправление кода не считается

- Состояния 166 кампаний, SMTP-счётчики и даты последних отправок совпали с копией
  непосредственно перед обновлением. Автоматический запуск остался выключен.
- Резервные копии исходников, PostgreSQL и файловых систем прежних контейнеров:

## Правила работы с почтой

- Запуск и возобновление кампаний, тестовые письма и ответы требуют явного
  разрешения пользователя. `OUTREACH_AUTOMATIC_SEND_ENABLED` оставляйте `false`.
- Ошибка получателя не должна отключать отправляющий ящик. SMTP и IMAP имеют
  независимые статусы; успешная проверка одного не подтверждает другой.
- `accepted` означает принятие письма SMTP-сервером после DATA, а не доставку
  во «Входящие». Ошибка сохранения IMAP-копии не разрешает повторную отправку.
- `uncertain` требует проверки фактического результата оператором. Ручная пауза,
  таймеры, история отправок и исключения должны сохраняться при обслуживании.
- Для диагностики сети без отправки: `python -m app.commands.check_mailboxes --network`
  внутри backend. `--verify` проверяет авторизацию и обновляет статусы ящиков.

## Проверки изменений

Из корня: `backend/.venv/bin/python -m pytest backend/tests -ra -o addopts=''`.
В `frontend/`: `node --test tests/conversation-http.test.mjs` и `npm run build`.
Проверка diff: `git diff --check`. PostgreSQL-варианты требуют отдельной тестовой БД.
Тесты, Git push, обновление сервера и реальный почтовый обмен проверяются отдельно.
