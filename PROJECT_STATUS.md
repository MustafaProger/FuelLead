## Реализовано

### Mail.ru и безопасное хранение

- Gmail API-клиент, Gmail CLI-команда и Gmail-тесты удалены.
- Добавлены ящики Mail.ru с фиксированными безопасными параметрами:
  - SMTP `smtp.mail.ru:465`, implicit SSL/TLS, обязательная авторизация полным email;
  - IMAP `imap.mail.ru:993`, SSL/TLS.
- Пароль внешнего приложения шифруется Fernet-ключом из `MAIL_CREDENTIALS_ENCRYPTION_KEY`.
- API и frontend никогда не возвращают `password` или `encrypted_password`; после сохранения показывается только «Пароль сохранён».
- Ошибки SMTP/IMAP очищаются от секрета, AUTH-команд, токенов и содержимого письма.
- Добавлена безопасная CLI-команда генерации ключа.

### Управление ящиками

- Отдельная страница «Почтовые ящики» позволяет:
  - добавить Mail.ru-ящик;
  - задать отображаемое имя, пароль внешнего приложения и дневной лимит;
  - включить/отключить SMTP и IMAP;
  - проверить SMTP-авторизацию без отправки;
  - отправить ровно одно тестовое письмо на вручную введённый и подтверждённый адрес;
  - приостановить/активировать ящик;
  - заменить пароль;
  - удалить неиспользуемый активной кампанией ящик после подтверждения.
- Карточка показывает состояние подключения, активность, последнюю проверку, прогрев, лимит, отправки сегодня, последнюю отправку и блокировку.

### Многопочтовый планировщик

- Одновременно допускается только одна активная кампания.
- Перед запуском создаётся снимок темы, текста, получателей, проверенных активных ящиков, лимитов и интервалов; подтверждение действительно 10 минут.
- Отправка последовательная: один ящик выполняет одну пачку, затем следующий; после полного круга сохраняется общий отдых.
- Интервал между письмами выбирается один раз в диапазоне 60–85 секунд и хранится в PostgreSQL.
- Отдых после круга выбирается один раз в диапазоне 77–93 минут и хранится в PostgreSQL.
- Размер пачки хранится отдельно для каждого ящика и растёт от 5 до 12 только после полностью успешной пачки без ошибок.
- Прогрев ящика сохраняется между кампаниями; дневной лимит имеет приоритет.
- Проблемный ящик прекращает текущую пачку и блокируется на три следующих полных круга; незапущенные письма остаются в общей очереди.
- PostgreSQL row locks и атомарный `claim_token` защищают одно письмо от двух worker-процессов.
- Перед каждым SMTP-вызовом повторно проверяются компания, её активность/статус/email, глобальное исключение, отсутствие предыдущей отправки и допустимый статус кампании.
- Нарушение проверки даёт `suppressed` без SMTP-вызова.
- Обрыв после начала SMTP-попытки без доказуемого ответа даёт `uncertain`, запрещает автоповтор и переводит кампанию в `interrupted`.
- Пауза запрещает новые SMTP-попытки, но сохраняет таймеры. Необратимая остановка переводит оставшиеся `queued` в `cancelled`.

### Статусы и результаты

- Delivery: `queued`, `sending`, `accepted`, `failed`, `bounced`, `uncertain`, `suppressed`, `cancelled`.
- Campaign: `draft`, `running`, `paused`, `cooldown`, `interrupted`, `completed`, `stopped`.
- `accepted` означает только принятие сервером после DATA, а не подтверждённую доставку или попадание во «Входящие»; это явно написано в интерфейсе.
- Для принятого письма сохраняются безопасный SMTP response, Message-ID, sender account и время.
- Постоянный адресный отказ классифицируется по SMTP/DSN-коду, а не только по строке `550 5.1.1`.

### Глобальные исключения и IMAP

- Добавлена страница «Исключения»: просмотр, поиск, ручное добавление и осторожное снятие.
- Исключения проверяются при создании снимка и прямо перед SMTP-вызовом.
- Отдельный Compose-сервис `imap-worker` читает новые DSN по UID только для активных ящиков с включённым IMAP.
- DSN сопоставляется по Message-ID и техническим заголовкам; поздний bounce переводит `accepted` в `bounced` и добавляет email в глобальные исключения.
- Обработка идемпотентна; позиция UID сохраняется. Нераспознанные письма не удаляются и полностью не логируются.

### Наблюдаемость

- Диалог кампании показывает круг, активный ящик, позицию в пачке, следующий запуск, окончание отдыха и счётчики всех delivery-статусов.
- Логи отправки структурированы и используют идентификаторы/безопасные коды без паролей, токенов и текста писем.

## Как локально подключить три ящика

1. Сгенерировать Fernet-ключ без сохранения в репозиторий:

   ```bash
   docker compose run --rm --no-deps backend python -m app.commands.generate_mail_credentials_key
   ```

2. Вставить выведенный ключ только в игнорируемый локальный `.env`:

   ```dotenv
   MAIL_CREDENTIALS_ENCRYPTION_KEY=...
   OUTREACH_AUTOMATIC_SEND_ENABLED=false
   ```

3. Пересоздать сервисы, чтобы они прочитали новый `.env`:

   ```bash
   docker compose up -d --build --force-recreate backend imap-worker
   docker compose restart frontend
   ```

4. Открыть `http://localhost:8080/#mailboxes` → «Почтовые ящики».
5. По очереди добавить:
   - `artel.work@mail.ru`
   - `mustafa.tojiev.2005@mail.ru`
   - `artel.office8@mail.ru`
6. Для каждого вставить новый пароль внешнего приложения именно в поле «Пароль внешнего приложения», задать лимит и нажать «Добавить ящик».
7. Нажать «Проверить» у каждого ящика. Эта кнопка авторизуется по SMTP, но письмо не отправляет.
8. IMAP включать только там, где нужен сбор возвратов. «Тестовое письмо» использовать отдельно и только с вручную введённым подтверждённым адресом.

Пароли ящиков нельзя помещать в `.env`, коммитить, отправлять в чат или повторно использовать после компрометации.
